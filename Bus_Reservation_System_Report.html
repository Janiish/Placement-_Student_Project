1. Introduction

The Bus Reservation System (BusVoyager) is a full-stack web application designed to simplify the process of searching for buses, selecting seats, and booking tickets online. The system replaces traditional manual ticket-booking counters with a modern, user-friendly digital interface backed by a robust REST API.

Built using Spring Boot 3.4 on the backend and vanilla HTML/CSS/JavaScript with Tailwind CSS on the frontend, the application demonstrates enterprise-grade development practices including layered architecture, DTO pattern, global exception handling, and MongoDB as the persistence store.

1.1 Problem Statement

India's intercity bus network serves millions of passengers daily. However, many operators still rely on manual or fragmented systems for seat allocation, leading to:

  • Long queues and delayed departures at bus terminals.
  • Overbooking or under-utilisation of bus capacity.
  • Lack of real-time seat availability information for passengers.
  • No centralised record of bookings for auditing or analytics.

A digital reservation system addresses every one of these pain points while improving customer satisfaction and operational efficiency.

1.2 Objectives

  1. Develop a RESTful backend API using Spring Boot and MongoDB to manage buses, routes, and bookings.
  2. Create an intuitive, responsive frontend for passengers to search buses, view seat maps, and book tickets.
  3. Implement real-time seat availability tracking with conflict detection to prevent double-booking.
  4. Apply clean software engineering practices: layered architecture, DTO pattern, centralised error handling, and CORS configuration.
  5. Provide seed data and a database schema for easy project setup and demonstration.

1.3 Scope

The current version of the system covers:

  • Bus search by origin, destination, and travel date.
  • Interactive seat selection with a visual 2+2 seat map.
  • Booking creation with passenger details and fare calculation.
  • Booking confirmation with a printable ticket.
  • City listing fetched dynamically from the database.

Out of scope (for this version): user authentication, payment gateway integration, admin panel, and cancellation/refund workflows.

2. Literature Review

Online reservation systems have been extensively studied in the fields of e-commerce, transportation, and enterprise application design. This chapter surveys the key technologies and architectural patterns adopted in this project.

2.1 Spring Boot & REST API Design

Spring Boot, part of the Spring ecosystem, provides convention-over-configuration for building production-ready applications. Its embedded Tomcat server, auto-configuration, and starter dependencies drastically reduce boilerplate. RESTful API design—mapping HTTP verbs (GET, POST, PUT, DELETE) to CRUD operations—has become the de-facto standard for client-server communication in modern web development (Fielding, 2000).

2.2 NoSQL Databases — MongoDB

MongoDB is a document-oriented NoSQL database that stores data in flexible, JSON-like documents. For applications with rapidly evolving schemas or nested data (e.g., seat number arrays within bookings), MongoDB provides superior flexibility over rigid relational schemas. Spring Data MongoDB offers repository abstractions that eliminate hand-written CRUD queries (MongoDB Inc., 2024).

2.3 Frontend Technologies

Modern frontends leverage utility-first CSS frameworks such as Tailwind CSS for rapid UI development. Combined with the Fetch API for asynchronous HTTP calls, single-page experiences can be built without heavy framework overhead (React, Angular). The BusVoyager frontend adopts this lightweight approach while delivering a premium glassmorphism aesthetic.

2.4 Layered Architecture & DTO Pattern

The three-tier architecture (Controller → Service → Repository) separates concerns, improves testability, and allows independent evolution of layers. Data Transfer Objects (DTOs) decouple the API contract from internal entity models, preventing unintended data exposure and offering flexibility for API versioning (Fowler, 2002).

5.3 Backend — Service Layer

Services encapsulate all business logic. They interact with repositories and return DTOs to controllers.

5.3.1 BusService.java

@Service
@RequiredArgsConstructor
public class BusService {
    private final BusRepository busRepository;
    private final BookingRepository bookingRepository;
    private final RouteRepository routeRepository;

    public List<BusSearchResponse> searchBuses(String from, String to, String dateStr) {
        LocalDate travelDate = LocalDate.parse(dateStr);
        String day = travelDate.getDayOfWeek().name().substring(0, 3);

        List<Route> routes = routeRepository
            .findByOriginIgnoreCaseAndDestinationIgnoreCase(from, to);
        if (routes.isEmpty()) return Collections.emptyList();

        return busRepository.findByRoute(routes.get(0)).stream()
            .filter(bus -> bus.getOperatingDays() != null
                        && bus.getOperatingDays().contains(day))
            .map(bus -> {
                int booked = countBookedSeats(bus.getId(), travelDate);
                return new BusSearchResponse(bus.getId(), bus.getBusName(),
                    bus.getBusNumber(), bus.getBusType(), bus.getTotalSeats(),
                    bus.getDepartureTime(), bus.getArrivalTime(), bus.getFare(),
                    bus.getRoute().getOrigin(), bus.getRoute().getDestination(),
                    bus.getTotalSeats() - booked);
            }).collect(Collectors.toList());
    }

    public SeatAvailabilityResponse getSeatAvailability(String busId, String dateStr) {
        LocalDate travelDate = LocalDate.parse(dateStr);
        Bus bus = busRepository.findById(busId)
            .orElseThrow(() -> new RuntimeException("Bus not found"));

        List<Integer> bookedSeats = bookingRepository
            .findByBusIdAndTravelDateAndStatus(busId, travelDate, "CONFIRMED")
            .stream().filter(b -> b.getSeatNumbers() != null)
            .flatMap(b -> b.getSeatNumbers().stream())
            .distinct().collect(Collectors.toList());

        return new SeatAvailabilityResponse(
            bus.getId(), bus.getBusName(), bus.getTotalSeats(),
            bookedSeats, bus.getFare());
    }

    public List<String> getAllCities() {
        return routeRepository.findAll().stream()
            .flatMap(r -> List.of(r.getOrigin(), r.getDestination()).stream())
            .distinct().sorted().collect(Collectors.toList());
    }

    private int countBookedSeats(String busId, LocalDate date) {
        return bookingRepository
            .findByBusIdAndTravelDateAndStatus(busId, date, "CONFIRMED")
            .stream().filter(b -> b.getSeatNumbers() != null)
            .mapToInt(b -> b.getSeatNumbers().size()).sum();
    }
}

5.3.2 BookingService.java

@Service
@RequiredArgsConstructor
public class BookingService {
    private final BookingRepository bookingRepository;
    private final BusRepository busRepository;

    @Transactional
    public BookingResponse createBooking(BookingRequest request) {
        Bus bus = busRepository.findById(request.getBusId())
            .orElseThrow(() -> new RuntimeException("Bus not found"));

        LocalDate travelDate = LocalDate.parse(request.getTravelDate());
        Set<Integer> bookedSeats = getBookedSeatNumbers(bus.getId(), travelDate);

        for (Integer seatNo : request.getSeatNumbers()) {
            if (seatNo < 1 || seatNo > bus.getTotalSeats())
                throw new RuntimeException("Invalid seat number: " + seatNo);
            if (bookedSeats.contains(seatNo))
                throw new RuntimeException("Seat already booked: " + seatNo);
        }

        Booking booking = new Booking();
        booking.setPassengerName(request.getPassengerName());
        booking.setPassengerEmail(request.getPassengerEmail());
        booking.setPassengerPhone(request.getPassengerPhone());
        booking.setBus(bus);
        booking.setTravelDate(travelDate);
        booking.setTotalFare(bus.getFare()
            .multiply(BigDecimal.valueOf(request.getSeatNumbers().size())));
        booking.setSeatNumbers(request.getSeatNumbers());
        booking.setStatus("CONFIRMED");
        booking.setBookingTime(LocalDateTime.now());

        return mapToResponse(bookingRepository.save(booking));
    }

    public BookingResponse getBooking(String id) {
        return mapToResponse(bookingRepository.findById(id)
            .orElseThrow(() -> new RuntimeException("Booking not found")));
    }

    private Set<Integer> getBookedSeatNumbers(String busId, LocalDate date) {
        return bookingRepository
            .findByBusIdAndTravelDateAndStatus(busId, date, "CONFIRMED")
            .stream().filter(b -> b.getSeatNumbers() != null)
            .flatMap(b -> b.getSeatNumbers().stream())
            .collect(Collectors.toSet());
    }

    private BookingResponse mapToResponse(Booking b) {
        return new BookingResponse(b.getId(), b.getPassengerName(),
            b.getPassengerEmail(), b.getPassengerPhone(),
            b.getBus().getBusName(), b.getBus().getBusNumber(),
            b.getBus().getRoute().getOrigin(),
            b.getBus().getRoute().getDestination(),
            b.getTravelDate(), b.getSeatNumbers(),
            b.getTotalFare(), b.getStatus(), b.getBookingTime());
    }
}

5.6 Backend — Configuration & Exception Handling

5.6.1 CorsConfig.java

Enables Cross-Origin Resource Sharing for all origins, allowing the frontend (served from a different port or file) to communicate with the backend.

@Configuration
public class CorsConfig {
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/**")
                    .allowedOrigins("*")
                    .allowedMethods("*")
                    .allowedHeaders("*");
            }
        };
    }
}

5.6.2 GlobalExceptionHandler.java

Centralised exception handling returns structured JSON error responses instead of stack traces.

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(RuntimeException.class)
    public ResponseEntity<Map<String, String>> handleRuntimeException(
            RuntimeException ex) {
        return ResponseEntity.badRequest()
            .body(Map.of("error", ex.getMessage()));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, String>> handleException(Exception ex) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(Map.of("error", "An unexpected error occurred: "
                + ex.getMessage()));
    }
}

9. Conclusion

The Bus Reservation System (BusVoyager) successfully demonstrates the design and implementation of a full-stack web application using modern Java technologies. The project achieves its stated objectives:

  • A clean, layered Spring Boot backend with RESTful APIs for bus search, seat availability, and booking management.
  • MongoDB as a flexible NoSQL datastore with Spring Data repository abstractions.
  • A visually premium frontend with interactive seat selection, real-time fare calculation, and printable booking tickets.
  • Robust error handling and graceful fallback behaviour when the backend is unavailable.
  • Comprehensive seed data covering multiple routes, buses, and sample bookings for immediate demonstration.

The project follows industry-standard practices including DTO pattern, global exception handling, CORS configuration, and responsive design. The modular architecture makes it easy to extend with authentication, payments, and admin features in future versions.

This project has been an excellent learning experience in full-stack development, covering backend API design, database modelling, frontend interactivity, and software engineering best practices.

Appendix — Database Schema & Seed Data (schema.sql)

-- ============================================================
-- Bus Reservation System - Database Schema & Seed Data
-- ============================================================

CREATE DATABASE IF NOT EXISTS bus_reservation;
USE bus_reservation;

-- Drop existing tables
DROP TABLE IF EXISTS bookings;
DROP TABLE IF EXISTS buses;
DROP TABLE IF EXISTS routes;
DROP TABLE IF EXISTS users;

-- Table: users
CREATE TABLE users (
  id        BIGINT AUTO_INCREMENT PRIMARY KEY,
  name      VARCHAR(100) NOT NULL,
  email     VARCHAR(100) NOT NULL UNIQUE,
  phone     VARCHAR(15),
  password_hash VARCHAR(255),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Table: routes
CREATE TABLE routes (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  origin      VARCHAR(100) NOT NULL,
  destination VARCHAR(100) NOT NULL,
  distance_km INT
);

-- Table: buses
CREATE TABLE buses (
  id             BIGINT AUTO_INCREMENT PRIMARY KEY,
  bus_name       VARCHAR(100) NOT NULL,
  bus_number     VARCHAR(20)  NOT NULL,
  bus_type       ENUM('AC','NON_AC','SLEEPER','SEMI_SLEEPER') NOT NULL,
  total_seats    INT DEFAULT 40,
  route_id       BIGINT NOT NULL,
  departure_time TIME NOT NULL,
  arrival_time   TIME NOT NULL,
  fare           DECIMAL(10,2) NOT NULL,
  operating_days VARCHAR(100) DEFAULT 'MON,TUE,WED,THU,FRI,SAT,SUN',
  FOREIGN KEY (route_id) REFERENCES routes(id) ON DELETE CASCADE
);

-- Table: bookings
CREATE TABLE bookings (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  passenger_name  VARCHAR(100) NOT NULL,
  passenger_email VARCHAR(100) NOT NULL,
  passenger_phone VARCHAR(15),
  bus_id          BIGINT NOT NULL,
  travel_date     DATE NOT NULL,
  seat_numbers    TEXT NOT NULL,
  total_fare      DECIMAL(10,2) NOT NULL,
  status          ENUM('CONFIRMED','CANCELLED') DEFAULT 'CONFIRMED',
  booking_time    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (bus_id) REFERENCES buses(id) ON DELETE CASCADE
);
